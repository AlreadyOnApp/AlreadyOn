# Branding

[![AlreadyOn](../web/public/branding/header-doc.svg)](../README.md)

**Your library, tuned to you**

The approved identity combines the On Air television icon with rounded geometric AlreadyOn lettering. Blue accents, white lettering and charcoal surfaces match the application's dark theme. Keep the wording and capitalization consistent.

## Assets

[Full logo](../web/public/branding/logo.svg), [header](../web/public/branding/header-doc.svg), [dark banner](../web/public/branding/banner.svg), [icon](../web/public/branding/icon.svg) and [wordmark](../web/public/branding/wordmark.svg) are generated by `python3 scripts/generate-branding.py`.

The script defines the shared shapes and palette. It produces the browser favicon and Android in-app/launcher vector resources from the same paths. Edit the generator and regenerate all outputs together; do not modify individual copies. Lettering is outlined, with no downloaded font dependency. Supporting tagline text uses the platform's standard font.

Use the header in constrained navigation, the full logo on authentication screens, and the dark banner where the surrounding documentation theme may be light. Scale the icon uniformly to 105% of the adjacent AlreadyOn wordmark height. Align their bottom edges on one line; the tagline sits closely below the wordmark with half the original gap and does not affect icon size. Logo and title links return to the application home/guide; documentation logos link to the project README. Leave space around the artwork. Android adaptive icons keep the mark inside the mask-safe area; older launchers have a fallback drawable.

Brand changes require visual checks at desktop and narrow browser widths and an Android build. Physical-device appearance still needs separate verification. Application behavior and release gates are unchanged.
